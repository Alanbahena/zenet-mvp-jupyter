# Subtask 7.2 — Chat panel update (`gradio_app/components.py`)

## Context

**Parent task:** Task 7 — Bienvenida Section: Welcome Agent + Onboarding Form
**Source of truth:** `.taskmaster/docs/task-7/plan.md`

This subtask adds `initial_messages` support to `render_chat_panel()` so the
Bienvenida tab can inject Zeni's static auto-greeting without an LLM call.
It is a single backwards-compatible function signature change.

**Prior (7.1):** Delivered `WelcomeAgent`. No direct code dependency — 7.2 touches
only `components.py` and does not import `WelcomeAgent`.

**Next (7.3):** `bienvenida.py` calls `render_chat_panel(..., initial_messages=[greeting])`
and cannot display the auto-greeting until this parameter exists.

---

| In scope | Out of scope |

## Architectural Decisions

### Decision 1: `initial_messages` defaults to `None`

**Choice:** `initial_messages: list[dict[str, str]] | None = None`

**Rationale:** Backwards-compatible — all existing callers (section stubs for Tasks
8–12) pass no `initial_messages` argument. Default `None` means `gr.Chatbot` starts
with an empty history, which is the current behaviour.

---

### Decision 2: Static string, no LLM call

**Choice:** The greeting passed via `initial_messages` is a hardcoded string defined
in `bienvenida.py`, not generated by the agent.

**Rationale:** Faster tab load, no API cost, always consistent. Defined in `bienvenida.py`
(subtask 7.3) — `components.py` is agnostic to the content.

---

### Decision 3: Add `type="messages"` explicitly to `gr.Chatbot`

**Choice:** Pass `type="messages"` to `gr.Chatbot(...)` even though Gradio 6.8.0
defaults to messages format.

**Rationale:** The parent plan flags this as an open risk. Being explicit removes any
ambiguity about format expectations and future-proofs against Gradio version changes.
Verified installed version: Gradio 6.8.0.

## Risks and Open Questions

1. **`initial_messages` message format.** `gr.Chatbot` with `type="messages"` expects
   `list[dict]` with keys `"role"` (`"user"` | `"assistant"`) and `"content"` (`str`).
   The `_INITIAL_GREETING` defined in 7.3 must use this format exactly. If the dict
   keys are wrong, Gradio will either silently ignore the messages or raise a runtime
   error. Verified format expectation from `components.py` docstring line 19.

2. **`value=None` on `gr.Chatbot`.** Passing `value=None` is safe in Gradio 6.x —
   it renders an empty chatbot. No special-casing needed.
